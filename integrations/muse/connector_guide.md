# 部署与真实接入
1. 在你授权的服务器启动容器（目前未购买、未创建外部账号、未发布）。准备域名 A/AAAA 指向服务器。
2. 在反向代理配置有效 TLS 证书，转发 /mcp 到 127.0.0.1:8000，保留 Authorization 和 Host。SENTINEL_ALLOWED_HOSTS 配置实际域名；不要用通配所有主机。请求体限制256KiB、超时30秒、单实例请求限流建议每分钟60次。关闭请求体、Authorization 和查询参数日志。公网只开放443，不开放8000。
3. 健康检查只表明服务进程可达，不证明 Muse 已连接或监控开启。生成随机 token，通过安全凭据流程写入 Muse；本版单用户单实例，不与其他用户共享 token。轮换后旧 token 失效。
4. 使用 setup_prompt.md 请求 Custom Connector。官方帮助确认该流程存在；公开文档未给出完整客户端传输/认证兼容矩阵。我们的实现是 Streamable HTTP + Bearer，不声称 Muse 已验证支持；如果它要求 OAuth，则需要后续实现真实 OAuth，不能把静态 token 假装成 OAuth。
5. Muse 列工具、调用 status、扫描合成邮件，再选择已授权 Gmail 测试邮件，检查证据和通知。记录工具名、任务ID、结果时间及权限失败，不记录正文或凭据。
6. 若自定义客户端不支持此协议，先提供实际错误；不要自动使用未知代理或泄露凭据。

下一步需要用户提供：拟使用的域名与服务器/托管方式，以及对部署的授权。真实 Muse 账户的连接与安全输入由用户完成或明确授权操作；无需交出 Gmail 密码。
